Introduction

Normalyze API

A REST API that converts raw Indian bank transaction strings into strictly-typed, deterministic JSON. Built for fintech developers and AI agents.

Send messy strings like UPI/ZOMATO/98123456/FOOD or POS/BPCL PETROL/NEW DELHI and get back structured data with merchant name, category, channel, confidence score, and an explain field showing exactly how the result was produced.

Beta: You get 10,000 free API calls during beta. No card required. Generate a key →

Base URL

https://normalyzerapi.vercel.app

How it works

The engine runs in two stages. First, a vectorized Pandas rules engine matches ~90% of transactions deterministically using a keyword map of 200+ Indian vendors. Anything it can't match falls through to Gemini 2.0 Flash as a fallback. Every response carries a ruleset_version field so your results are stable across deploys.

Quickstart

Up in 2 minutes

  1. Generate an API key at normalyzerapi.vercel.app with your email. Your key starts with nyz_live_.

  2. Send your first request:

curl
curl -X POST https://normalyzerapi.vercel.app/v1/normalize/batch \ -H "Authorization: Bearer nyz_live_your_key_here" \ -H "Content-Type: application/json" \ -d '{"transactions": [ "UPI/ZOMATO/98123456/FOOD", "POS/BPCL PETROL/NEW DELHI", "NEFT/SALARY/CR/ACME CORP LTD", "REFUND/SWIGGY/REF982341/ORIG881234" ]}'

  1. Parse the response — every result has a merchant, category, channel, confidence score, and explain field.

response
{ "status": "success", "count": 4, "data": [{ "raw_string": "UPI/ZOMATO/98123456/FOOD", "clean_merchant": "Zomato", "category": "Food and Beverage", "transaction_type": "debit", "channel": "upi", "is_reversal": false, "is_partial": false, "ruleset_version": "v1.0.0", "explain": { "path": "keyword_match", "rule": "zomato → Food and Beverage", "model": null, "confidence": 0.95, "ruleset_version": "v1.0.0" } }, // ... 3 more results ] }

Authentication

API keys

All endpoints (except key generation) require an API key passed as a Bearer token in the Authorization header.

header
Authorization: Bearer nyz_live_<your_key>

Keys are prefixed with nyz_live_ followed by 32 hex characters. The raw key is shown once at generation — store it in an environment variable immediately.

Security: Only the bcrypt hash of your key is stored. If you lose it, revoke it and generate a new one.

Endpoints

Normalize batch

POST/v1/normalize/batch

Normalizes an array of raw transaction strings. Up to 500 strings per request. This is the primary endpoint for bulk processing.

Request body

json
{ "transactions": ["string"] // array of raw strings, max 500 }

Response fields

FieldTypeDescription
statusstring"success" on all 2xx responses
countintegerNumber of transactions processed
dataarrayArray of normalized transaction objects
data[].raw_stringstringOriginal input string echoed back
data[].clean_merchantstringNormalized merchant name
data[].categorystringSpend category (see categories reference)
data[].transaction_typestring"debit", "credit", or "unknown"
data[].channelstring"upi", "neft", "imps", "pos", "atm", etc.
data[].is_reversalbooleanTrue if string contains REFUND/REV/CHARGEBACK
data[].is_partialbooleanTrue if string contains SPLIT/PART/PARTIAL
data[].normalized_timestampstring|nullISO 8601 timestamp if parseable
data[].ruleset_versionstringRuleset version used (e.g. "v1.0.0")
data[].explainobjectClassification path and confidence (see below)

The explain object

FieldTypeDescription
explain.pathstring"keyword_match", "gemini_fallback", or "unmatched"
explain.rulestring|nullWhich keyword fired, e.g. "zomato → Food and Beverage"
explain.modelstring|null"gemini-2.0-flash" if fallback was used, else null
explain.confidencefloat0.95 / 0.85 / 0.65 / 0.10 (see confidence reference)
explain.ruleset_versionstringLocked ruleset version for determinism

Normalize single transaction

POST/v1/normalize/transaction

Normalizes a single transaction string. Useful for real-time processing or agent workflows.

json
{ "transaction": "UPI/ZOMATO/98123456/FOOD" }

Returns a single normalized transaction object (not wrapped in an array).

Normalize CSV

POST/v1/normalize/csv

Upload a CSV file directly. Auto-detects Indian bank column formats including Narration, Description, and Particulars — rename to raw if auto-detection fails.

Required CSV columns

ColumnRequiredNotes
rawYesRaw transaction string
idNoYour transaction ID, echoed back
amountNoNumeric amount
timestampNoDate/time string in any common format
curl
curl -X POST https://normalyzerapi.vercel.app/v1/normalize/csv \ -H "Authorization: Bearer nyz_live_your_key" \ -F "file=@transactions.csv"

Generate API key

POST/v1/keys/generate

Self-serve key generation. No auth required. The raw key is returned once and cannot be retrieved again.

json
{ "email": "you@company.dev" }

One key per email address. If a key already exists for your email, revoke it first before generating a new one. Returns 409 on duplicate.

Get key usage

GET/v1/keys?email=you@company.dev

Returns usage stats for your API key — total calls, total transactions processed, and last used timestamp.

Revoke API key

POST/v1/keys/revoke

Immediately deactivates the key associated with your email. Use this if your key has been exposed.

json
{ "email": "you@company.dev" }

Confidence scores

The explain.confidence field indicates how certain the classification is. Use this to decide which results to trust automatically and which to route for human review.

ScorePathMeaning
0.95keyword_matchKeyword matched at the start of the string — strong signal
0.85keyword_matchKeyword matched anywhere in the string
0.65gemini_fallbackClassified by Gemini — treat with moderate confidence
0.10unmatchedCould not be classified — verify manually

Recommended threshold: Trust results with confidence ≥ 0.85 automatically. Route 0.65 results through a spot-check queue. Flag 0.10 results for manual review.

AI agent guide

Normalyze is designed to be agent-readable. The OpenAPI spec is available at /openapi.json and the Swagger UI at /docs.

Recommended error handling

pseudocode
// Recommended agent error handling if status == 401: refresh_api_key() if status == 422: inspect detail[].loc and fix schema if status == 429: halt and surface upgrade prompt if status == 500: retry once with backoff, then surface error // Trust thresholds if confidence >= 0.85: auto_process() if confidence == 0.65: queue_for_spot_check() if confidence == 0.10: flag_for_manual_review()

Idempotency note

The deterministic rules engine (≥0.85 confidence) always returns the same result for the same input + ruleset version. The Gemini fallback (0.65) is non-deterministic — if idempotency matters for your pipeline, cache results using SHA-256(raw_string + ruleset_version) as the cache key.
